Other bugs found and fixed
--------------------------
- URL patterns: "https://*.github.com/*" also matched https://evil.example/?a.github.com/
  (scripts and settings ran on unrelated sites) and did not match github.com itself.
- URL matching could freeze the UI thread for seconds/minutes on very long URLs (regex backtracking).
- web.block did not apply to cross-origin iframes (deprecated WebView2 request filter).
- Favicon downloads bypassed web.block (made by the app itself, including redirects).
- Top-bar extension buttons could push Settings off-screen; extras now go into a "»" menu.
- Many launcher buttons ran off the top of the window; they now wrap into columns and avoid the
  history panel.
- A hand-edited or damaged settings.json reset everything and was overwritten on exit; it is now
  kept as settings.json.unreadable-<time>, numbers/booleans in SettingValues are accepted, and
  keys differing only by case no longer crash startup.
- Number settings could store decimals (e.g. "8.5") that reset to the default after Save; values
  typed but not confirmed before pressing Save were lost.
- Select defaults kept the wrong casing; ids accepted a trailing newline; non-Latin file names
  produced random or colliding ids; whitespace-only text defaults were dropped.
- Importing could overwrite another extension's file.
- app.log lines were written for disabled extensions and repeated on every Save; extension text
  could forge extra log lines.
- Extension pages could open untracked popup windows (now opened as protected tabs instead).
- web.css was blocked by strict Content-Security-Policy (now a constructable style sheet; CSS that
  uses @import keeps a <style> element because constructable sheets drop @import).
- A web.script with a syntax error failed silently; it is now logged once.
- Invalid app.startpage values replaced the user's own start page with the default.
- Settings editors leaked window handles on every selection change; '&' in extension labels was
  shown as a keyboard shortcut.
- MainForm.cs had 43 lines ending in CR CR LF (from the Copilot autofix commits); normalised to CRLF
  so git treats the file as text again.

Ultrareview follow-up (10 findings, all confirmed in the code and fixed)
------------------------------------------------------------------------
- Extension windows: a plain link in ui.html navigated the window to the website (no web.block, no way
  back). Web links now open in a protected tab, and web.block applies to what extension windows load.
- MessageBoxes and the Import file picker were visible to screen capture. All app dialogs now get
  the same capture exclusion as the main window (and follow protection changes while open).
- Host matching: "ad.tracker.example." (trailing dot) slipped past "*.tracker.example" rules, and
  Unicode hosts in patterns ("*.bücher.de") never matched. Both fixed (C# matcher + in-page guard).
- Editing an installed file so its meta.id matches another installed extension silently dropped
  that entry and orphaned its file. It is now left alone and reported in the log.
- Two PhantomHaze windows could erase each other's extension installs (each overwrote settings.json
  on exit). Exit no longer overwrites a file another window changed, and Save merges the other
  window's installs/uninstalls first.
- Favicon downloads could follow an https -> http redirect (plain-text request). Now refused.
- web.block did not cover service/shared worker requests. Now covered (filter kept on one tab).
- A failed rollback deleted the only copy of the previous extension source, and startup deleted
  leftover backups. Such backups are now kept (extensions\recovered\ for leftovers).
- Duplicate helper code in MainForm now reuses the parser's rules (id derivation could differ).
- The Settings extension list rebuilt the details panel three times per refresh; now once.
